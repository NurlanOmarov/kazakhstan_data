# Развёртывание на сервере (доступ по IP, без домена)

Система разворачивается через Docker Compose: контейнер приложения
(gunicorn + uvicorn) за nginx с self-signed HTTPS. Наружу открыт только nginx.

## Требования к серверу

- Docker + Docker Compose
- Диск: см. README (≈ размер БД + небольшой запас на логи/индексы)
- ОЗУ: рекомендуется ≥ 4 ГБ (SQLite mmap + кэш страниц)
- Открытые порты: 443 (https), 80 (редирект на https)

## Шаги

```bash
# 1. Скопировать проект на сервер и перейти в каталог
cd Kazakhstan_data

# 2. Положить базы в ./data (монтируется в контейнер)
#    РЕКОМЕНДУЕТСЯ: сделать ./data сжатым томом (12 ГБ -> ~3 ГБ, без потери
#    скорости). См. COMPRESSION.md, вариант B:
#      sudo ./deploy/setup-compressed-volume.sh 16G
mkdir -p data
cp /путь/kazakhstan_data.db data/
#   users.db будет создан автоматически при инициализации (шаг 5)

# 3. Настроить секреты
cp .env.example .env
#   - сгенерировать KZ_JWT_SECRET:
python3 -c "import secrets; print(secrets.token_hex(32))"
#   - вписать его в .env, задать KZ_ADMIN_PASSWORD

# 4. Сгенерировать self-signed сертификат под IP сервера
./deploy/gen-cert.sh 203.0.113.10      # <- ваш IP

# 5. Инициализировать БД пользователей и админа (один раз)
docker compose run --rm app python init_users.py

# 6. Запустить
docker compose up -d --build

# Открыть https://203.0.113.10  (браузер один раз предупредит о
# самоподписанном сертификате — это нормально для доступа по IP)
```

## Эксплуатация

```bash
docker compose logs -f app           # логи приложения (включая аудит-вход)
docker compose restart app           # перезапуск
docker compose down                  # остановка
```

- **Аудит** доступа смотрите в админке («Журнал действий») или в `users.db`,
  таблица `audit_log`.
- **Бэкап**: достаточно копировать `data/users.db` (учётки + аудит).
  `kazakhstan_data.db` статична — бэкапить один раз.
- **Смена секрета JWT** инвалидирует все активные сессии (потребуется
  повторный вход) — это нормально при инциденте.

## Замечания по безопасности (IP без домена)

- Доменного имени нет → используется self-signed сертификат с IP в SAN.
  Трафик шифруется; для доверенного сертификата нужен домен и Let's Encrypt.
- Рекомендуется ограничить доступ к портам 80/443 списком IP (firewall/
  security group) или завести за VPN — это сильнее всего снижает риск.
- Все мутирующие запросы защищены httpOnly + SameSite=Strict cookie и
  ролевой моделью.
