# Безопасность сервиса

Система обрабатывает персональные данные (~16 млн записей: ФИО, ИИН, телефоны,
адреса). Ниже — модель защиты и результаты аудита ИБ.

## Реализованные меры

**Аутентификация и сессии**
- Пароли — bcrypt (соль на каждый пароль).
- Сессия — JWT (HS256) в cookie с флагами `HttpOnly`, `SameSite=Strict`,
  `Secure` (на HTTPS). Срок 8 ч.
- Секрет JWT — из `KZ_JWT_SECRET` (обязателен в проде, един для всех воркеров).
- **Отзыв сессий**: смена пароля/`revoke_tokens` повышают `token_version` —
  все ранее выданные токены немедленно становятся невалидными.
- **Блокировка перебора**: накопительный счётчик неудачных входов (не
  обнуляется при блокировке), эскалация времени блокировки. Плюс rate-limit
  на `/api/login` (приложение 10/мин + nginx 10/мин/IP).

**Авторизация**
- Роли `user` / `admin`. Роль перечитывается из БД на каждом запросе
  (понижение прав применяется сразу, без ожидания истечения токена).
- Защита от самоблокировки/самопонижения/самоудаления админа.
- Валидация и приведение типов во всех админ-эндпоинтах (роль, лимиты, флаги).

**Защита от инъекций**
- Все SQL-запросы параметризованы (`?`). Имена колонок — только из
  доверенных словарей.
- `ORDER BY` — строго по белому списку колонок.
- **FTS5**: пользовательский ввод санитизируется (удаляются спецсимволы
  `" * : ^ ( ) { } [ ] - + ~`), значение оборачивается во фразу — исключает
  FTS-инъекцию, перенацеливание колонок и DoS на дорогих запросах.

**Защита данных**
- Основная БД открыта **только на чтение** (`mode=ro` + `PRAGMA query_only`).
- Тексты ошибок БД наружу не отдаются (логируются на сервере, клиенту —
  обобщённое сообщение). `/api/health` не раскрывает объём/детали.
- `/docs`, `/redoc`, `/openapi.json` отключены.
- В ответах нет паролей/хешей; служебные поля убираются.

**Защита от массового скачивания**
- Дневные квоты на поиск (500) и экспорт (10×2000 строк), настраиваемые
  глобально и индивидуально на пользователя.
- Полный **аудит** всех действий (вход/выход/поиск/экспорт/соседи/действия
  админа): кто, когда, IP, объём результата, параметры.
- Автодополнение — от 2 символов (защита от перебора ПДн).

**Транспорт и инфраструктура**
- HTTPS (self-signed под IP), современные шифры, `TLSv1.2/1.3`,
  `ssl_session_tickets off`.
- Security-заголовки: CSP, `X-Frame-Options: DENY`, `nosniff`,
  `Referrer-Policy`, `Permissions-Policy`.
- Контейнер: непривилегированный пользователь, `no-new-privileges`,
  основная БД смонтирована `:ro`, приложение наружу не публикуется (только
  через nginx).
- ПДн не попадают в access-логи (логи nginx/gunicorn без query-string).

## Результаты аудита

Проведён аудит (независимый разбор кода). Все находки **Critical/High**
устранены: FTS-инъекция, обязательность JWT-секрета, утечка ошибок БД,
слабая блокировка, валидация админ-операций, TLS-конфиг. Закрыты и ключевые
Medium: ПДн в логах, отзыв сессий, лимиты экспорта, минимальная длина suggest.

Покрытие тестами: **backend 46** (вкл. отдельный `test_security.py` —
инъекции, блокировка, отзыв токенов, гейтинг ролей) + **frontend 9**.

## Рекомендации при эксплуатации (организационные)

- Ограничить доступ к портам 80/443 списком IP (firewall) или VPN — для
  доступа по IP это самая эффективная мера.
- Регулярно просматривать «Журнал действий» на аномалии (всплески поиска/
  экспорта).
- Хранить `KZ_JWT_SECRET` и `.env` в секрете; ротировать при инциденте
  (это завершит все сессии).
- Резервное копирование `users.db` (учётки + аудит).

## Известные ограничения

- Self-signed сертификат по IP вызывает предупреждение браузера (нет домена
  для доверенного сертификата). Канал при этом шифруется.
- Дедупликация записей и расширенные антифрод-эвристики — вне текущего объёма.
